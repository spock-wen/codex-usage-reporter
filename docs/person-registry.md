# 管理员维护人员名册

看板按邮箱把 Codex 用量归并到人员。人员名册存于服务端 SQLite 的 `people_registry` 表，只能由管理员 API 读取或替换，不写入源码仓库或部署包。旧数据库启动时会自动创建该表，不需要清库。

使用管理员 Bearer 密钥：

- `GET /api/people` 返回当前完整名册。
- `PUT /api/people` 用请求中的完整列表原子替换名册。请先保存 GET 返回结果；更新时提交所有仍需保留的人员，空列表会清空名册。
- 兼容接口 `GET /api/users` 保留原来的 `users` 字段，并额外返回同一份 `people` 列表，供现有看板加载。

请求体格式如下，示例为虚构数据：

```json
{
  "people": [
    {"email": "person@example.com", "name": "Example Person", "department": "Example Team"}
  ]
}
```

邮箱会去除首尾空格并转换为小写；邮箱不能重复，姓名和部门必须是非空文本且最多 200 字。单次最多 10,000 条。服务端先校验整份列表，校验通过后才在一个事务中替换，因此无效请求不会清除旧名册。接口仅接受管理员认证，不要把管理员密钥放进同事的 skill、浏览器页面或仓库。
